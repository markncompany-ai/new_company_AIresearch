# 혁신의숲 기업 등록 — 1차 조사

혁신의숲 기업 등록을 위한 1차 조사를 수행한다. 결과는 검수 작업대에 붙여넣을 JSON으로 출력하고 `기업등록/결과/` 폴더에 저장한다.

> 서비스 판정 세부 목록(회사소개 경로·앵커 패턴, 공유 플랫폼 호스트, 커머스 접미어, 제외 사유 어휘, 함정 목록)은
> **`references/서비스판정규칙.md`** 에 있다. 서비스 판정이 애매할 때 그 파일을 읽는다.

## 절대 원칙 (위반 시 작업 무효)

1. **실제 확인된 정보만 출력한다.** 추측·생성·조합 금지.
2. **URL은 검색 결과나 실제 페이지에서 본 것만 쓴다.** 홈페이지 주소에 제품명을 붙여 만드는 식의 조합은 절대 금지. (과거 실제 사고: `stradvision.com/svnet/`, 로고 경로를 임의 생성 → 둘 다 존재하지 않는 주소였음)
3. **확인 못 한 항목은 생략한다.** 억지로 채우지 않는다. 비어 있으면 사람이 채우지만, 가짜가 들어가면 그대로 등록되어 더 위험하다.
4. **유사 사명 주의.** 이름이 비슷한 다른 회사를 가져오지 않는다. 반드시 대표자명·사업자번호로 교차 확인한다. 확신이 없으면 비운다.
   - 실제 사례: "씨쓰리브이"(대표 강연주) vs "씨브이쓰리"(대표 양진호) — 완전히 다른 회사
   - 실제 사례: "(주)알록"이 뷰티디바이스/폐업 전자상거래/의료기기 3곳 존재
5. **출처를 말할 수 있어야 한다.** 어디서 봤는지 설명 못 하는 값은 넣지 않는다.
6. **후보를 지우지 말고 사유를 붙여 남긴다.** 특히 서비스는 제외해도 `notes`에 사유를 적는다. 애매하면 `undecided`.
7. **뉴스는 무조건 최신순이다.** 네이버 뉴스 PC 최신순(`where=news&sort=1`)을 직접 열어 가장 최근 기사부터 **최소 5건, 최대 15건**을 담는다.
   WebSearch 결과만 보고 끝내면 최근 1~2년치를 통째로 놓친다. 오래된 기사로 5건을 채우는 것은 **작업 실패**다.
   **날짜는 반드시 기사 본문에서 확인한다** — 검색 목록 날짜와 구글 뉴스 RSS `pubDate`는 실제 발행일과 어긋난다. (3단계 참조)

## 조사 절차 (기업마다 반드시 이 순서로)

### 1단계: 기업 식별
- WebSearch로 기업명 검색. 결과가 애매하면 "기업명 + 대표자명"으로 재검색.
- **대표자명이 일치하는지 반드시 확인.** 불일치하면 다른 회사다.
- 사명 표기가 다르면(예: 스트라드비전 vs 스트라드비젼) 사용자에게 알린다.
- **기업명 검색만으로 홈페이지를 못 찾으면 아래 두 경로를 반드시 더 돌린다.** 셋은 서로 못 찾는 것을 메운다 —
  이름이 흔하면 ①이 막히고, 홈페이지에 번호를 안 적어 둔 회사는 ②가 막히고, 신설·소규모면 ③만 남는다.
  1. **사업자번호 역검색** — 검색창에 번호를 `123-45-67890` 형태(따옴표로 묶어)로 넣는다. 회사는 홈페이지 푸터·이용약관·쇼핑몰 안내에 사업자등록번호를 표시할 의무가 있어, 걸리면 그 회사 사이트가 맞다. **찾는 즉시 검증이 끝나므로 이름 검색보다 확실하다.**
     - 네이버 모바일 검색(`https://m.search.naver.com/search.naver?where=m_web&query=...`)이 잘 걸리고 차단도 없었다(2026-09-22, 25곳 표본 전부 정상·자체 도메인 3곳 발견).
     - 결과에 사업자정보 모음 사이트(비즈위키·머니핀·bizno·114 등)가 섞여 나온다. 이들은 홈페이지가 아니므로 결과에 쓰지 않되, **주소·업종·대표전화를 보완하는 용도로는 쓴다**(연락처 항목이 가장 많이 빈다).
  2. **기업명 + 대표자명 검색** — 동명 회사를 걸러 내는 데 효과가 있다(광철님 실사용 확인, 2026-09-22). 채용공고·보도자료·기관 공고에 둘이 같이 적히는 경우가 많다.
- **검색에 나온 후보 도메인은 상위 몇 개만 고르지 말고 전부(최대 10개) 열어본다.** 여는 비용은 싸고, 안 열어서 놓치는 손해가 훨씬 크다.
  - **순위를 "검색 결과에 많이 나온 순"으로 매기지 않는다.** 그러면 포털·커뮤니티·기업정보 디렉터리(디시인사이드·로컬비즈·비즈위키·테크월드 등)가 항상 위로 올라오고 진짜 회사 도메인이 밀린다. 이런 사이트는 후보에서 아예 제외한다.
  - 우선순위는 ① 도메인에 **사명 로마자/영문**이 들어 있는지 ② 사업자번호 일치 ③ 제목에 사명 포함 순이다.
  - **쇼핑몰 호스팅 주소도 자사 사이트 후보다** — `*.cafe24.com`·`*.cafe24api.com`, 아임웹(`imweb.me`), 식스샵, 고도몰, 윅스 등. 네이버 스마트스토어만 쇼핑몰로 보지 않는다.
  - 실제 사고(2026-09-28 광철님 지적): 이노젬의 `innogem.cafe24api.com`은 검색 결과 6위라 상위 4개만 열던 당시 규칙에 걸려 한 번도 열리지 않았다. 도메인에 사명이 그대로 들어 있고 사업자번호(539-49-00550)도 적혀 있어 열었으면 바로 확정됐다. 732곳에서 이렇게 열지 않고 넘어간 후보가 920개였다
- **번호가 다르다는 이유로 버린 후보는 그냥 버리지 말고 `notes`에 남긴다.** (예: `후보 mondjewel.com — 사이트 표기 사업자번호 불일치`) 검수자가 다시 처음부터 찾는 일을 막는다.

### 2단계: 홈페이지 직접 방문 (필수, 생략 금지)
- 검색 요약만 보고 끝내지 말 것. **반드시 홈페이지를 직접 열어서 확인한다.**
- **최상위 주소가 비어 보인다고 버리지 않는다.** 내용이 거의 없는 껍데기 루트(수십~수백 바이트) 뒤에 실제 사이트가 숨어 있는 경우가 많다. 다음을 순서대로 확인한 뒤에야 "없음"으로 판정한다.
  1. 검색 결과에 나온 **경로를 그대로** 연다. 루트(`/`)로 깎아서 열지 말 것
  2. 응답이 2KB 미만이면 `meta refresh`·`frame`/`iframe` `src`·`location.href` 를 읽어 **따라 들어간다**
  3. 그래도 없으면 `/webhome/`, `/main/`, `/home/`, `/kr/`, `/index.html` 같은 흔한 경로를 시도한다
  - 실제 사고(2026-09-26 광철님 지적): 한국위생연구소를 "홈페이지 미확보"로 처리했는데, `koreahlab.co.kr` 루트가 75바이트 껍데기였고 실제 사이트는 `koreahlab.co.kr/webhome/` 에 있었다. 그 페이지에 기업명과 사업자번호(669-81-02000)가 그대로 적혀 있었다. 732곳 중 91곳이 같은 함정이었다
- **검색으로 홈페이지가 안 나오면 후보 도메인을 직접 열어서 확인한다.** 웹검색은 해외 인덱스 기준이라 국내 `.co.kr`·`.kr` 도메인을 자주 놓친다.
  - 후보 생성: 영문 사명 기준 `<사명>.co.kr` → `.kr` → `.com` → `.net` 순으로 실제로 접속해 본다
  - **접속해서 그 회사가 맞다고 확인된 것만 기록한다.** 열어보지 않은 주소를 결과에 적는 것은 여전히 금지 — 열어서 확인하는 것은 추측이 아니라 검증이다
  - 열었는데 다른 회사이거나 접속이 안 되면 그 주소는 버리고 홈페이지를 생략한다
  - 실제 사고: (주)파마비전을 "홈페이지 없음"으로 처리했으나 `pharmavision.co.kr`이 실재했다. 검색에는 동명의 튀르키예·남아공 기업만 나왔고 후보 도메인을 열어보지 않은 것이 원인
- 먼저 WebFetch로 시도하고, 본문이 비어 나오거나 내용이 부실하면(JS 렌더링 사이트) **브라우저 도구(mcp__Claude_Browser__navigate → get_page_text)로 실제 렌더링해서 읽는다.** 그래도 안 보이면 screenshot으로 확인한다.
- **푸터(맨 아래)와 Contact/About 하위 페이지**에서 다음을 찾는다 (연락처가 하위 페이지에만 있는 경우가 많음):
  - 사업자등록번호 (이미지로 되어 있으면 screenshot/zoom으로 읽기 시도)
  - 대표 전화번호
  - 대표 이메일
  - 로고 이미지 주소 (페이지 소스에서 실제 확인된 주소만) — 아래 '로고 찾기' 절차대로
- **로고 찾기 — 다음을 전부 확인한다. 일부만 보고 "없음"으로 단정하지 않는다.**
  1. `header`/`nav` 안의 `img` (로고는 거의 항상 여기 있다)
  2. `alt`·`src`·`class`에 `logo`/`brand`/`ci`/`symbol`이 들어간 `img` — **`alt` 속성을 반드시 읽는다**
  3. CSS `background-image`, 인라인 `svg`
  4. `<link rel="icon">`, `og:image` 메타태그
  - **이미지 목록을 잘라 보지 않는다.** 전수로 훑고, 자사 로고와 고객사·파트너사 로고를 구분한다
  - **호스팅 도메인만 보고 판단하지 않는다.** 네이버 CDN(`pstatic.net`), 위블리·윅스(`wixstatic.com`), 카페24 등 외부 CDN에 올린 자사 로고가 흔하다. 자사 도메인이 아니라는 이유로 버리지 말고 `alt`와 위치로 판단한다
  - 실제 사고: 엔디넥스 헤더의 `alt="NDNEX Logo"`(849×376) 이미지를 `pstatic.net` 주소라는 이유로 지도 썸네일로 단정해 "로고 없음"으로 처리했다
  - 외부 CDN 주소면 끊길 수 있으므로 `notes`에 적어 검수자가 내려받아 보관하게 한다
- **동시에 상단 메뉴·푸터의 링크 목록을 수집해 둔다** — 4단계 서비스 찾기의 재료가 된다.
- 끝까지 읽을 수 없으면 그 사실을 보고에 적고 해당 항목은 생략한다.

### 3단계: 뉴스 검색
- **WebSearch만 믿지 말 것.** WebSearch는 해외 인덱스 기준이라 **국내 언론 기사, 특히 최근 1~2년치를 통째로 놓친다.**
  - 실제 사고: 일신오토클레이브를 WebSearch로만 찾아 2019~2024년 기사 5건만 넣었는데, 뉴스 탭에는 2025~2026년 기사가 5건 더 있었다. **결과가 부실하면 거기서 멈추지 말고 검색 경로를 바꿔 재검색한다.**
- **주 경로는 네이버 뉴스 PC 최신순이다** — `https://search.naver.com/search.naver?where=news&sort=1&query=<인코딩>` (2페이지는 `&start=11`).
  기사 직접 URL을 그대로 주고 차단도 없다. 모바일판(`m.search.naver.com`)은 무한스크롤이라 `start`가 안 먹고 10건에서 끊긴다. PC판도 질의에 따라 `start=11`이 1페이지와 같은 결과를 주는 경우가 있으니, **질의를 3~5가지로 바꿔 가며**(사명 단독 / 사명+대표자 / 사명+업종어 / 영문명) 후보를 모으는 쪽이 확실하다.
- **구글 뉴스는 보조로만 쓴다. 두 가지 함정이 있다(2026-10-20 실측, 10배치 전부 동일).**
  - 구글 뉴스 탭(`tbm=nws&tbs=sbd:1`)은 curl이면 JS 리다이렉트로 빈 응답, 내장 브라우저면 봇 감지(`/sorry/index`)에 막힌다. **Claude in Chrome**(`mcp__claude-in-chrome__*`)으로는 열리는 경우가 있다. CAPTCHA는 직접 풀지 말고 사용자에게 요청한다.
  - **구글 뉴스 RSS(`news.google.com/rss/search`)의 `pubDate`는 실제 발행일과 최대 3개월 어긋난다.** (실측: 쿠키뉴스 기사 RSS 2026-10-10 → 본문 2026-07-01) **목록 뽑는 용도로만 쓰고 날짜 근거로는 절대 쓰지 않는다.**
  - RSS로 제목만 잡히고 원문 URL을 못 구하는 기사도 생긴다. 그런 건은 넣지 말고 `notes`에 "제목은 확인됐으나 원문 URL 미확보"로 남긴다.
- 네이버 뉴스 목록의 날짜도 본문 날짜와 다를 수 있다(실측: 목록 2026.08.05 → 본문 2025-05-30). **날짜는 반드시 본문·메타태그에서 확인한다.**
- DDG HTML 검색(`html.duckduckgo.com/html/`)은 제목→URL 해결에 잘 듣지만 2~3회면 202로 막힌다.
- 회사 홈페이지의 News/보도자료 페이지도 확인한다. 단 자사 게시물은 뉴스가 아니므로 넣지 않는다.
- **허브에 이미 등록된 기업이면 기존 뉴스를 함께 확인한다** — `innoforest_search_companies`로 companyId를 얻고 `innoforest_get_news`로 조회. 기존 뉴스가 오래됐으면 새로 찾은 최신 기사를 보고에 명시한다.
- **최소 5건, 최대 15건**을 최신순으로 담는다. 5건을 못 채우면 그 사실을 보고에 적는다. 기간 제한 없음. **정확도 우선** — 동명 기업 기사는 제외.
- **기업이 주어가 아닌 기사는 제외한다** (업계 일반 기사, 관계사 대표 자격 인터뷰 등). 중고 장비 거래글·쇼핑몰 게시물도 뉴스가 아니다.
- 각 기사는 날짜/언론사/제목/URL 4개가 필요. **날짜는 기사 본문에서 확인한다** — 검색 결과의 '1개월 전' 같은 상대 표기나 URL 추정에 의존하지 않는다.

### 4단계: 서비스 찾기 (아래 '서비스 수집 규칙' 전체 적용)
수집원을 **모두** 돌린다. 하나라도 빠뜨리면 서비스를 덜 잡는다.
1. **홈페이지 링크** — 2단계에서 모아둔 메뉴·푸터 링크에서 후보 추출
2. **앱마켓** — 구글플레이 **와** 애플 앱스토어 **둘 다** 검색
3. **웹검색** — `"<기업명> 서비스"`, `"<기업명> 앱"` 등
4. **쇼핑몰 후보가 하나도 없으면** `"<기업명> 스마트스토어"`를 **최소 한 번** 반드시 검색

### 5단계: 소개글 작성
- **[참고] 소개(refIntro)**: 자유 서술. 사업 내용을 풍부하게(3~5문장). 카테고리·키워드 추출의 근거가 됨.
- **양식 소개글(intro)**: 아래 규칙 엄수.

## 기업소개글 양식 규칙

기본 문형: `☆☆기반 □□대상 ~~을 ○○하는 기업`

- 문장은 항상 **"기업"으로 끝난다.**
- ☆☆(수단/기술): AI 등 사업의 기초 기술이 있을 때만
- □□(대상): 타겟이 명시됐을 때만, 문장 앞쪽에
- ○○(액션): 제품 형태에 따라 — 앱/웹→개발·운영, 상품/하드웨어→개발·제조, 콘텐츠→제작·제공
- 서비스명은 작은따옴표: '스파인 리셋'. **서비스명이 없으면 생략한다.**
- 액션 2개 이상: 가나다순 + 마지막 앞에 '및' (예: 개발 및 제조)
- 서비스 2개 초과: 2개까지 나열 후 '등'
- **금지 표현**: 1등, 다양한, 간편, 최대, 쉽다, 전문, 누구나, 편리, 혁신, 최초, 프리미엄 등 주관적 문구
- 외래어는 한글로 (넷플릭스 O, Netflix X / 콘텐츠 O, 컨텐츠 X). 단 AI, SaaS, IoT 등 기술용어는 예외.
- **딥테크·바이오는 정확한 업계 용어를 쓴다.** (예: "모양기억 폴리머" X → "형상기억 고분자" O)
- **"플랫폼"은 웹서비스를 연상시키므로, 실제로 하드웨어/기기면 쓰지 않는다.**

## 이메일 판정 규칙

**우선순위 상**: support, info, hi, hello, contact, cs, help, ask, connect, 기업명@
**우선순위 중**: ceo, sales, marketing, ir@
**절대 금지**: tax, bill, finance, fn, account, accounting@ (세금·회계용)

**개인메일 도메인 처리** (개인정보 법적 리스크 — 엄격 준수)
대상 도메인: gmail.com · naver.com · hanmail.net · daum.net · nate.com · kakao.com · outlook.com · hotmail.com · yahoo.com · icloud.com

- 아이디가 **회사명·홈페이지 도메인과 일치**하거나 공용 계정명(info·contact 등)이면 → **수집하되 "검수 필요"로 표기**하고 사유를 적는다.
- 아이디가 회사명과 무관한 개인 이름·별칭이면 → **수집하지 않는다.**
- **일치 판정 방법**: 아이디를 구분자(`.` `_` `-`)와 숫자로 토막 낸 뒤, **3글자 이상인 토막**이 홈페이지 도메인 라벨과 서로 포함 관계면 회사 계정으로 본다. 3글자 미만 일치는 우연으로 보고 인정하지 않는다.
  - `playtown808@gmail.com` + `playtown.biz` → 토막 `playtown` = 도메인 `playtown` → **회사 계정**
  - `pharmavision_nu@naver.com` + `pharmavision.co.kr` → 토막 `pharmavision` = 도메인 `pharmavision` → **회사 계정** (접미사 `_nu`가 붙어도 인정)
  - `okpt@hanmail.net` + `physiorobo.co.kr` → 토막 `okpt`가 도메인과 무관 → **개인 메일, 제외**
- 이메일이 여러 개면 우선순위 높은 것 1개만.

| 유형 | 정의 | 수집 |

### 등록 규칙 8개 (노션 운영 매뉴얼 "C. 서비스/제품 & 방문자분석")

1. **서비스가 2개 이상이면 각각 별도 등록** — 서로 다른 웹/앱 URL 필요 (쿠팡 / 쿠팡이츠)
2. **회사 홈페이지는 서비스 URL이 아니다** — `bucketplace.com` X / `ohou.se` O
   - 예외: 그 홈페이지 주소의 이름이 등록 서비스명과 일치하면 남긴다
3. **소개만 하고 운영되지 않는 페이지 제외** — 실제 운영되는(로그인 등이 있는) 웹·앱만
   - `baemin.com` X, `doctornow.co.kr` X / `kurly.com/main` O
4. **여러 서비스를 한꺼번에 소개하는 통합 페이지 제외** (예: `wafour.com`)
   - 판정: 같은 메뉴 그룹 안에 서로 다른 목적지 링크가 여럿이면 그 부모 링크가 통합 소개 페이지
5. **같은 도메인의 하위 경로형 제품 라인은 각각 등록한다.**
   - 로플랫 → `loplat.com/loplat-x`, `/loplat-i`, `/loplat-dmp`, `/loplat-laas` **각각**
   - 서비스파인더 파이프라인은 트래픽 집계 때문에 호스트 단위로 묶지만, **1차 조사는 등록 기준(각각)을 따른다.** 같은 호스트 하위 경로임이 눈에 띄면 `notes`에 남겨 검수자가 판단하게 한다
6. **외부 루트 도메인도 등록 가능** — 스마트스토어·카페24·노션·아임웹 위에 올라간 서비스 OK. 단 링크가 실제로 열리는지 확인
7. **B2B SaaS, 폐쇄몰은 등록하지 않는다** (`b2b-saas` / `closed-mall`)
8. **앱은 구글플레이 + 애플 앱스토어 둘 다** 검색해 해당 기업 서비스로 확인되면 링크 전체 등록

### 올린다 / 안 올린다

**올린다**
- 웹 서비스 — 로그인·이용이 가능한 웹사이트/웹앱
- 앱 서비스 — 구글플레이 / 애플 앱스토어
- 커머스 서비스 — 온라인으로 상품·예약을 거래하는 서비스
- 이름 붙은 브랜드 — `®`·`™`·`(R)` 표시가 붙었거나 기업이 자사 브랜드로 내세우는 고유 이름 (물리 제품이라도 이름은 후보로 올린다)

**안 올린다**
- 만져지는 물건 그 자체 (화장품·식품·기기)
- **장비 모델 번호** — `PT-V10`·`CIB-1000A` 같은 영문+숫자 조합은 브랜드가 아님
- 회사 소개만 하는 홈페이지 / 회사소개류 페이지 (경로·앵커 목록은 references)
- 뉴스 기사·보도자료 그 자체

### 앱 판정

- **구글플레이와 애플 앱스토어를 둘 다** 검색한다
- 검색 결과에서 **개발사명이 일치할 때만** 채택
- 개발사 계정이 확인되면 그 계정의 **전체 앱을 역으로 확장**해서 수집
- **iOS와 구글플레이의 같은 앱은 하나로 통합**한다 (URL은 둘 다 기록)
- **동명 앱 함정**: 앱 이름이 회사명과 같아도 개발사가 다르면 남의 앱이다.
  - 실제 사례: MCN "플레이타운"을 검색하면 메타버스 농장 게임 "플레이타운"(개발사 1zlabs)이 나온다. 등록하면 안 된다
- 검색해도 그 기업 앱이 없으면 **앱은 없는 것.** URL을 추측해서 만들지 않는다

### 서비스명 규칙

- **영문명(`nameEn`)을 함께 넣는다.** 확인 우선순위 (1) 기업 홈페이지 표기 (2) 서비스 URL 도메인에서 추정(`ohou.se` → `ohouse`) (3) 보도자료. **애매하면 생략**
- 용도별 2개 버전이면 `_` + `~용`: `자란다_선생님용` / `자란다_부모님용`
- **이름 정리는 띄어쓰기·대소문자만.** 괄호와 밑줄은 지우지 않는다 (지우면 별개 서비스가 뭉개짐 — 실측 25건)
- 슬로건·메뉴 라벨로 보이는 이름(쉼표·느낌표 포함, `~합니다`/`~하세요` 종결)은 서비스명이 아닐 가능성이 높다 → references의 "이름다움" 판정 참조
- 언어 서브도메인(`en.` `cn.` 등)은 본체로 접는다 → references 참조

### 제외한 서비스는 사유를 남긴다

지우지 말고 `notes`에 `서비스 제외: <이름 또는 URL> (<사유>)` 형태로 적는다.
사유 어휘: `offline` / `other` / `b2b-saas` / `closed-mall` / `ownership-transferred` / `undecided`
**확신이 안 서면 무조건 `undecided`.** 그 기업 것이 맞는지 애매하면 지우지 말고 이유와 함께 남긴다.

## 출력 형식 (JSON)

**확인된 항목만 쓴다. 빈 항목은 키 자체를 생략한다.** (생략하면 작업대가 자동으로 빈 값 처리, 빈 문자열도 쓰지 말 것)

**값 안에 곧은 큰따옴표(`"`)를 쓰지 않는다.** 뉴스 제목처럼 원문에 큰따옴표가 있으면 둥근 따옴표 `“ ”`로 바꿔 넣는다.
`\"`로 이스케이프하면 JSON 자체는 유효하지만, 채팅에서 복사할 때 역슬래시가 떨어져 나가 작업대에서 "Unterminated string in JSON" 오류가 난다 (실제 사고: 일신오토클레이브 뉴스 제목 3건).
작은따옴표 `'`는 이스케이프가 필요 없으므로 그대로 써도 된다.

```json
[
  {
    "name": "기업명",
    "cp": "CP00040459",
    "bizno": "000-00-00000",
    "ceo": "대표자국문명",
    "homepage": "https://...",
    "logo": "https://...",
    "phone": "02-000-0000",
    "email": "contact@...",
    "sns": ["https://linkedin.com/..."],
    "refIntro": "참고용 자유서술 3~5문장",
    "intro": "양식 소개글",
    "introEn": "영문 소개글 (intro가 있을 때만)",
    "cats": ["1순위", "2순위", "3순위"],
    "aiKws": ["키워드1", "키워드2", "키워드3", "키워드4", "키워드5"],
    "services": [{"type": "웹", "name": "서비스명", "nameEn": "ServiceName", "url": "https://..."}],
    "news": [{"date": "YYYY-MM-DD", "press": "언론사", "title": "제목", "url": "https://..."}],
    "notes": ["검수 포인트 — 대표자 불일치, 동명회사 제외 이력, 개인메일 수집 사유, 서비스 제외 사유 등"]
  }
]
```

**단축 규칙**:
- **`cp` (기업 ID)**: 사용자가 요청에 기업 ID를 같이 준 기업만 넣는다. **조사해서 알아내는 값이 아니다 — 안 주면 키를 생략한다.** 받은 형태가 `40459`든 `CP40459`든 `CP00040459`든 그대로 넣으면 작업대가 `CP+8자리`로 맞춰서 해당 기업 카드에 자동 매칭한다(뉴스 엑셀 복사의 CORP_ID 칸에도 자동으로 들어감)
- 대표자 1명이면 `"ceo": "이름"` 한 줄. 공동대표만 `"reps": [{"name":"A","sns":[]}, {"name":"B","sns":[]}]` 사용
- **`services`**: `type`은 `"웹"` 또는 `"앱"`. `nameEn`은 확인됐을 때만 넣고 애매하면 키를 생략한다. iOS·구글플레이 둘 다 있으면 같은 `name`으로 각 스토어 URL을 하나씩 항목으로 넣는다
- 뉴스는 배열만 쓰면 국내로 처리. 국외 기사가 있을 때만 `"news": {"domestic":[...], "foreign":[...]}` 형태 사용
- 정보가 거의 없는 기업은 3~4줄로 끝나도 정상 (예: `[{"name":"씨쓰리브이","bizno":"754-88-03723","ceo":"강연주"}]`)
- **`notes`**: 검수자가 봐야 할 주의사항은 채팅 보고가 아니라 이 배열에 기업별로 적는다 (검수작업대가 "검수 포인트" 박스로 표시). 제외한 서비스 사유도 여기 적는다. 없으면 생략
- **`introEn`**: intro를 작성했으면 영문 번역도 함께 넣는다 (검수작업대의 번역 버튼은 로컬 HTML에서 작동하지 않으므로 조사 단계에서 채워야 함). 규칙: 기업명 대신 "A company"로 시작, 작은따옴표 서비스명은 공식 영문명이 확인되면 그것을, 아니면 원문 그대로 유지, 비즈니스 문체

## 마무리 절차 (반드시 순서대로)

1. JSON을 `기업등록/결과/YYYY-MM-DD_기업명.json` 파일로 저장한다 (여러 기업이면 `YYYY-MM-DD_일괄N건.json`).
2. 채팅에도 JSON 전문을 코드블록으로 출력한다 (검수 작업대에 바로 복사할 수 있게).
3. JSON 아래에 다음을 짧게 보고한다:
   - 찾지 못한 항목과 그 이유
   - 유사 사명·동명이인 등 주의사항
   - 사명 표기가 다른 경우
   - 홈페이지를 읽을 수 없었던 경우
   - "검수 필요" 표기한 항목과 사유
   - **제외한 서비스와 사유** (특히 `undecided`)
4. 검수는 `기업등록/검수작업대.html`을 브라우저로 열어 JSON을 붙여넣으면 된다고 안내한다.
