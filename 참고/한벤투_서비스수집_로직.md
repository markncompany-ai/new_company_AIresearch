# 서비스 수집 로직 v2 (2026-08-07, 운영팀 검수 반영)

## 0. 수집 대상 정의
- **실제 운영 중인** 일반 사용자 대상 웹/앱 서비스 (플레이스토어 등록 앱, 웹 서비스, 자사몰·스마트스토어, 웹 형태 모바일 URL 포함)
- 제외: 기업 소개용 홈페이지, 오프라인 시설·프랜차이즈 자체, 입점몰(G마켓 미니샵 등), 타사 호스팅 팬페이지(비스테이지 등), B2B 솔루션 소개 페이지
- 자사몰은 등록 홈페이지와 같은 도메인이어도 **포함**

## 1. 기업 분류 (트리아지)
기업명·홈페이지 도메인·업종 정보로 서비스 보유 가능성을 먼저 판단한다.

- **고가능성** (심층 탐색): 게임·콘텐츠, 플랫폼·커머스, 교육, 헬스케어 앱, 소비자 브랜드(식품·뷰티·패션·펫), 핀테크, O2O
- **저가능성** (1회 확인 후 판단): 제조·소재·바이오R&D·건설·설비 등 B2B — "B2B는 서비스 없는 게 정상"이 기본값이나, 반드시 1회는 검색으로 확인 (예외 사례: 볼빅몰, 리츠 빈스캐너 앱)

## 2. 탐색 순서 (기업당)
1. **일반 검색**: `기업명 + 서비스/앱` — 사업 내용과 서비스 존재 파악
2. **공식 홈페이지 방문**: 서비스/APP 소개 페이지, 푸터의 앱 다운로드 링크 확인 (사업자번호로 동일 기업 교차 확인)
3. **앱 탐색**: 플레이스토어 검색 → 앱 발견 시 **개발사 페이지를 열어 앱 전수 나열** (관리자용·원장님용 등 파생 앱 포함)
4. **웹↔앱 상호 확인**: 앱을 찾았으면 전용 웹 존재 확인, 웹을 찾았으면 앱 존재 확인 → 같은 서비스면 한 행으로 통합
5. **자사몰 탐색**: 서비스 전용 도메인 → 홈페이지 내 몰 → `기업명 스마트스토어` 검색 순
6. **유사 사명 경계**: 동명 기업·서비스 발견 시 대표자명·사업자번호·도메인·패키지명으로 교차 확인 (예: 세이프인 3개사, Rocats≠로켓츠게임즈)

## 3. 검증 단계 (수집 후 전건)
1. **URL 생존 확인**: 웹 URL·플레이스토어 URL 실제 접속. 실패 시:
   - 신규 URL 재탐색 (패키지 변경·도메인 이전 케이스) → 찾으면 교체
   - 못 찾으면 "종료 추정"으로 제외
2. **귀속(소유권) 판정**:
   - 앱: **스토어 등록 명의(퍼블리셔) 기준** — 개발 외주작은 해당 기업 서비스 아님
   - 패키지명·도메인이 기업과 일치하는지 확인 (kr.keumyoung ↔ 금영)
   - **M&A·사업부 매각 뉴스 1회 확인** — 소유권이 넘어갔으면 제외
3. **중복 제거**: 같은 IP의 리브랜딩·신구버전은 1건으로 통합
4. **운영 상태 의심 시그널**: 관련 기사가 수년 전뿐 + 홈페이지 접속 불가 + 스토어 미검색 → 종료 추정

## 4. 판정 원칙 (기업등록 원칙 계승)
- 실제 확인한 URL만 기재 — **URL 조합·추측 생성 금지**
- 확인 못 한 항목은 비운다 (영문명 포함 — 스토어 영문 타이틀·도메인·패키지명 등 근거 있는 것만)
- 확신 못 하는 건은 비고에 사유를 남겨 검수자가 판단하게 한다

## 5. 기록 양식 (엑셀 .xlsx)
컬럼: `노출상태 | 유형선택 | corp id | 기업·기관명 | 서비스명 | 검수 통과 여부 | 서비스명(영문) | 유형 | 웹 URL | 플레이스토어 URL | 플레이스토어 URL 축약본 | 비고`

- 신규 요청 건: 노출상태·유형선택·검수 통과 여부 **공란**
- 서비스명: 한글 정식명만 (괄호 영문 병기 금지, 영문은 별도 컬럼)
- 유형: 웹 / 앱 / 웹·앱 (같은 서비스의 웹+앱은 한 행)
- 웹 URL: 데스크톱 URL (m. 모바일 URL 금지)
- 플레이스토어 URL 축약본: `id=` 뒤 패키지명만 (어드민 입력용)
- 서비스 없는 기업도 `없음` 행으로 포함 (비고에 업종·사유) → 커버리지 확인용
- 1행 = 서비스 1개, 기업당 개수 제한 없음

## 5-1. 공식 수집 정책 반영 (2026-08-07 추가)

**웹 URL 판별 — "살아있는가"가 아니라 "서비스가 구동되는 페이지인가"**
- 기업 홈페이지 X (bucketplace.com ✗ / ohou.se ○)
- **서비스 소개만 하고 운영되지 않는 랜딩 페이지 X** (baemin.com ✗, doctornow.co.kr ✗) — 앱 전용 서비스는 웹 URL을 비운다
- 실제 구동 페이지만 O: 로그인·예매·구매 등 서비스 기능 존재 (kurly.com ○)
- 여러 서비스를 한꺼번에 소개하는 페이지 X (wafour.com ✗)
- (2024.03.12~) **외부 도메인 등록 가능**: 스마트스토어·카페24·노션 등. 단 링크 정상 오픈 필수 확인

**B2B 판정 기준 (2026-08-07 운영매니저 확정)**
- 홈페이지 내 B2B 제품군 **설명 URL은 서비스가 아님** → 제외 (로플랫式 설명 페이지 등록은 이 작업에 적용하지 않음)
- 단, **B2B 제품이라도 별도 운영 웹/앱 URL이 있으면 수집** — 제품 가동에 쓰이는 앱, 고객사 로그인 웹 등 (사례: 리스크제로 관리자앱·제로가드, LITS 빈스캐너, 플러터, 글로벌텍스프리 가맹점용)
- 즉 "B2B라서 제외"가 아니라 "구동되는 별도 URL이 없어서 제외"가 맞는 논리

**수집 범위 (이 작업 한정)**
- **온라인 서비스만 수집** — 오프라인 시설·매장은 대상 아님 (일반 기업등록과 다른 점)

**앱 URL**
- 어드민에는 플레이스토어 URL의 `id=` 뒤 패키지명만 등록 (축약본)
- iOS 링크 별도 리스트업은 **일반 기업등록 정책**이며, **한벤투 서비스 수집에서는 iOS URL 수집 안 함** (2026-08-07 운영매니저 확정)

**유형선택**: 온라인/오프라인/기타 다중 체크 가능 (온라인 = 웹·앱 운영 시)

## 6. 알려진 한계
- 검색 엔진에 안 잡히는 최신·소규모 서비스는 놓칠 수 있음 (케인시스 사례)
- 홈페이지가 접속 불가(인증서 오류 등)면 그 기업 탐색 깊이가 얕아짐 — 비고에 명시
- 앱스토어(iOS) 전용 앱은 플레이스토어 축약본이 없음 — 비고에 iOS URL 기재
